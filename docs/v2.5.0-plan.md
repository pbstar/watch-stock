# 摸鱼看盘 v2.5.0 重构方案

> 分支：`v2.5` ｜ 状态：已定稿 ｜ 日期：2026-09-24

## 一、背景与目标

### 1.1 现状问题

当前"查看股票"是一个**编辑器标签页**（`WebviewPanel`，`ViewColumn.One`），和"摸鱼"二字的初衷相违背：

| 问题 | 表现 | 暴露程度 |
| --- | --- | --- |
| 位置显眼 | 占满整个编辑器区域，把代码挤到后台 | 高 |
| 标签页暴露 | 编辑器 tab 标题是「查看股票」，内部 tab 栏又是「A股全览 / 贵州茅台 / …」 | 高 |
| 视觉像行情软件 | 26px 大号价格、卡片边框、面积渐变分时图、240px 大图 + 成交量柱 | 高 |
| 数据不会动 | 打开后只是一张快照，要手动点「刷新」，逼得人盯着按钮 | 中 |

2.4.0 开发期曾在原面板上做过"低调化"（`ee3046a`：标题伪装、chip 流、sparkline），后在 `1b03147` 回退。本方案吸取那次的经验：**不在"编辑器标签页"这个错误的容器里做减法，而是换容器**；同时保留回退时明确要留的东西（`enableColorful` 彩色视图配置、一键隐藏行为）。

### 1.2 本版本目标

1. **隐蔽**：把看盘界面从编辑器区搬到底部面板，外观向"终端 / 输出日志"靠拢，瞥一眼分不清是在跑 watch 还是在看盘。
2. **实时**：面板可见时跟随主循环自动刷新，复用状态栏已拉到的数据，不额外增加请求。
3. **精简**：webview 代码从"HTML 片段 + 正则抽取 script + 全局变量隐式耦合"改为类型化的 TS 模块；顺带清理若干冗余类型、死代码与不一致写法。

### 1.3 非目标

- 不新增数据源、不改封单/大单/闹钟的判定逻辑。
- 不引入任何第三方运行时依赖（图表继续手写 SVG）。
- 不做 K 线、五档、资金流等新功能。

## 二、Webview 重构设计（核心）

### 2.1 容器：编辑器标签页 → 底部面板视图

用 `WebviewView`（`registerWebviewViewProvider`）替代 `WebviewPanel`，注册到**底部面板**（与终端、输出、问题并列）：

```jsonc
// package.json（示意）
"viewsContainers": {
  "panel": [{ "id": "watch-stock", "title": "WATCH-STOCK", "icon": "images/panel.svg" }]
},
"views": {
  "watch-stock": [{
    "type": "webview",
    "id": "watch-stock.view",
    "name": "WATCH-STOCK",
    "icon": "images/panel.svg",
    "when": "watch-stock.show"
  }]
}
```

选择底部面板的理由：

- 开发者本来就常开着终端面板，多一个 tab 毫不突兀；编辑器区完全留给代码。
- 面板高度有限（约 200~300px），天然约束我们只放"文本密度高、视觉面积小"的内容。
- 用户可以按 VS Code 原生能力把它拖到侧边栏/辅助侧边栏，不需要我们额外做"位置配置"。
- tab 名 `WATCH-STOCK` 与插件 ID 一致，全大写英文，混在 `PROBLEMS / OUTPUT / TERMINAL` 中像一个普通工具面板，没有中文"股票"字样那么扎眼。
- 旧的编辑器标签页模式**直接移除**，不保留切换开关（保留等于保留暴露面）。

#### 一键隐藏（老板键）

**同时控制状态栏与面板视图**，延续 2.4.0「隐藏时同步关闭股票面板」的行为，一次按键清除所有看盘痕迹。

| 操作 | 状态栏 | 面板视图 |
| --- | --- | --- |
| 一键隐藏 | 显示 `$(eye-closed)` | `setContext("watch-stock.show", false)`，`WATCH-STOCK` tab 从面板中消失，webview 随之销毁、停止推送 |
| 恢复显示 | 恢复行情 | `setContext("watch-stock.show", true)`，tab 回到面板但**不主动聚焦**，避免恢复瞬间"跳"出行情 |

- **不执行 `workbench.action.closePanel`**：用户可能把视图拖到了侧边栏，此时关面板会误关正在用的终端；且扩展 API 无法得知视图当前所在位置。tab 消失后面板会自动切到终端/输出等其他 tab，画面已是正常开发界面，无需再关面板。
- 快捷键 `Cmd+Alt+S` / `Ctrl+Alt+S` 不变，焦点在视图内时同样生效。
- **只有手动一键隐藏影响视图**；`autoHideByMarket` 休市自动隐藏只作用于状态栏，不收起视图（休市不是需要藏的场景，且休市时视图仍可查看收盘数据）。即：`watch-stock.show = (userForced !== false)`，与状态栏的三态逻辑解耦。

#### 启动恢复

- VS Code 会记住面板最后停留的 tab。若关闭编辑器时停在 `WATCH-STOCK`，下次启动会直接打开它——这是换到底部面板后新增的暴露风险，旧编辑器标签页不做恢复，没有此问题。
- 应对：`when` 使用正向键 `watch-stock.show`（而非 `!watch-stock.hidden`）——上下文键在激活前未设置、按 false 处理，启动瞬间视图不存在；`activate` 中再 `setContext("watch-stock.show", true)`，tab 延迟出现但不获得焦点。
- 需 F5 验证 VS Code 在视图延迟出现后是否仍会切回它（官方文档未明确）；若仍会切回，退路是激活后若视图 `visible` 则执行 `workbench.action.terminal.focus` 切回终端。

### 2.2 视觉：终端 / 日志风格

总原则：**像 `ls -l` 的输出，不像行情软件**。

- 字体：`--vscode-editor-font-family` 等宽字体，字号跟随编辑器；数字列右对齐。
- 颜色：默认全部使用 `editor-foreground` / `descriptionForeground`，无卡片、无边框、无渐变、无 emoji、无大号数字。
- `enableColorful` 保留：开启后涨跌色改用 `--vscode-terminal-ansiRed / ansiGreen`，跟终端配色主题一致，彩色模式下也"像终端输出"。
- 界面框架文字与股票名称均使用中文（`自选 / 指数 / 板块`、`暂无数据`），用短词、不加修饰；股票名称跟随 `showMiniName` / `stockMiniNames`，与状态栏保持一致。
- 行 hover 使用 `list.hoverBackground`，与原生列表一致。

- **自选**：自选股逐行列出，列：代码 / 名称 / 现价 / 涨跌幅 / 涨跌值 / 封单（仅涨跌停时出现）。排序跟随 `stockSortType`。
- **行内展开**：点击某行，在其下方展开详情（2 行指标 + 64px 细线分时图 + 24px 成交量柱），同一时间只展开一行；再点收起。取代原先的「个股 tab + 240px 大图 + 80px 成交量」。
- **成交量柱**：保留在展开区，与分时图共用横轴；默认单色（编辑器前景色，涨柱不透明度高、跌柱低，沿用现有黑白模式的明暗区分），`enableColorful` 开启时按涨跌着色；不画坐标框，仅左上角标注最大量。
- **分时图 hover**：不再弹浮层 tooltip，十字竖线贯穿分时图与成交量，把当前时刻的 `时间 价格 涨跌 成交量` 写进指标行末尾，视觉噪音更小。
- **指数**：5 个大盘指数，同自选的行格式。
- **板块**：行业板块按涨幅排序，等宽网格流式排布（`名称 +x.xx%`），一屏可见全部 46 个。

原界面内容去向（旧的「A股全览」拆为「指数」「板块」两个 tab，内容不丢）：

| 原界面 | 新界面 |
| --- | --- |
| 「A股全览」· 大盘指数（5 张卡片） | 「指数」tab，每个指数一行，格式同自选 |
| 「A股全览」· 行业板块（46 张卡片，按涨幅排序） | 「板块」tab，按涨幅排序，紧凑网格 |
| 两个区块各自的「↻ 刷新」按钮 | 顶栏一个「↻」，刷新当前 tab |
| 默认打开「A股全览」 | 默认打开「自选」，之后记住上次所在 tab |
| 每只股票一个 tab | 「自选」列表，点击行内展开详情 |

拆开的理由：底部面板约 260px 高，5 行指数 + 46 个板块同屏约 15 行，必然滚动；拆开后每个 tab 一屏可见，且「指数 / 板块」比「A股全览」字面上更平淡。

### 2.3 数据流：跟随主循环，自选行情零额外请求

```text
refresher（交易时间每 5 秒）
  → getStockList(stocks)            ← 已有请求
  → 状态栏渲染
  → stockView.pushStocks(stockInfos) ← 新增：视图可见才推送，复用同一份数据
       └ 若当前 tab 为指数/板块：视图自行拉取对应代码（仅可见时）
       └ 若有展开行：拉取该股腾讯完整行情 + 分时（分时沿用 10s TTL 缓存）
```

- 打开视图时直接使用 refresher 最近一次的行情（refresher 保存 `lastStockInfos`），**秒开**，不再像现在这样先并发三批请求、再整页重建 HTML。
- 视图不可见（切到终端 tab、面板收起、老板键）时停止一切推送与拉取。
- 非交易时间定时器跳过刷新，视图展示最近数据，保留手动 `↻`。
- 配置变更（`enableColorful`、`showMiniName`、`stockMiniNames`、`stockSortType` 等）走第三节 #10 的统一刷新入口，视图随之收到 `settings` 消息并重新渲染，无需重新打开。

### 2.4 生命周期与状态

- `retainContextWhenHidden` 关闭（省内存，也避免后台还挂着一个行情页面）。
- 视图内的轻量 UI 状态（当前 tab、展开的代码）用 webview 的 `getState/setState` 保存，重新可见时恢复。
- HTML 只在 `resolveWebviewView` 时设置一次，此后一律 `postMessage` 增量更新；视图重新可见时 webview 会重新加载并再次发送 `ready`，扩展端据此补发最新数据。

### 2.5 代码结构：HTML 片段 → 类型化 TS 模块

现状问题：

- `stockHome.ts` 用正则 `extractScript / stripScript` 从 4 个 HTML 片段里抠 `<script>` 再拼接，片段之间靠全局变量隐式耦合（`stockChart.html` 直接用 `stockDetail.html` 里声明的 `chartSvg`、`stockHome.html` 里的 `fmtVol`）。
- 扩展端与 webview 之间的消息没有类型约束，字段改名只能靠肉眼对齐。
- `esbuild.config.mjs` 里自写的 HTML 压缩正则（去注释、去 `//`）比较脆弱，需要为占位符专门开后门。

新结构：

```text
src/
├── shared/
│   └── protocol.ts        # 扩展 ⇄ webview 消息类型（两端共同 import）
├── ui/
│   ├── statusBar.ts
│   └── stockView.ts       # WebviewViewProvider（替代 stockHome.ts）
└── webview/               # 浏览器端，独立 tsconfig（lib: DOM）
    ├── tsconfig.json
    ├── main.ts            # 入口：消息分发、tab 切换、状态恢复
    ├── list.ts            # 自选 / 指数行渲染 + 行内展开
    ├── sector.ts          # 板块网格
    ├── chart.ts           # 细线分时图 + 成交量柱（SVG）
    ├── format.ts          # 数字/金额格式化
    └── style.css
```

构建（esbuild 官方能力，无新增依赖）：

- 新增第二个 entry：`src/webview/main.ts` → `dist/webview.js`（`platform: browser`、`format: iife`），CSS 一并产出 `dist/webview.css`。
- HTML 外壳只剩十几行，写在 `stockView.ts` 里，通过 `webview.asWebviewUri` 引用 `dist/` 资源；CSP 改为 `style-src ${cspSource}; script-src 'nonce-…'`，不再需要 `'unsafe-inline'`。
- 删除 `htmlMinifyPlugin`、`global.d.ts` 中的 `*.html` 模块声明、4 个 HTML 模板。
- `npm run typecheck` 增加 `tsc -p src/webview`，webview 端也纳入类型检查。

消息协议（`shared/protocol.ts` 草案）：

```ts
// 扩展 → webview
type ToView =
  | { type: "stocks"; items: Stock[]; time: string }
  | { type: "market"; kind: "index" | "sector"; items: MarketItem[] }
  | { type: "detail"; code: string; quote: StockQuote | null; minute: MinutePoint[] }
  | { type: "settings"; colorful: boolean; showMiniName: boolean; miniNames: Record<string, string> };

// webview → 扩展
type ToHost =
  | { type: "ready" }
  | { type: "tab"; kind: "mine" | "index" | "sector" }
  | { type: "expand"; code: string | null }
  | { type: "refresh" };
```

## 三、其他精简与修正

| # | 位置 | 现状 | 调整 |
| --- | --- | --- | --- |
| 1 | `types.ts` `StockOverview` + `stockHome.ts#convertToStockInfo` | 与 `StockQuote` 重复的子集类型，只为改个 `close → preClose` | 删除，webview 直接用 `StockQuote` |
| 2 | `types.ts` `StockQuote` | `avgPrice / circulatingShares / totalShares` 解析了但无人使用 | 删除字段及解析 |
| 3 | `types.ts` `SendMsgOptions.showConfirm` | 无任何调用方传入 | 删除，`sendMsg` 签名同步简化 |
| 4 | `types.ts` `StatusBar` 接口 / `getStatusBarItem()!` | 接口只是类的镜像；状态栏 item 既被推进 `context.subscriptions` 又在 `deactivate` 里手动 dispose（双重释放） | 删接口，`AppState` 直接持有 `StatusBarManager`；统一由 `context.subscriptions` 释放 |
| 5 | `alarmManager.ts` 两处 `stockInfos.find` | 与 2.3.2 起"Map 索引替代循环内 find"的约定不一致 | 改为 Map |
| 6 | `config.ts` | 158 行里 90 行是指数/行业常量，与"配置访问入口"职责混在一起 | 常量移到 `src/constants.ts`，`config.ts` 只管配置读写 |
| 7 | `http.ts` | 不检查 `res.ok`，接口 4xx/5xx 时把错误页当行情解析 | 非 2xx 直接抛错，由上层已有 try/catch 兜底 |
| 8 | `commands.ts` `COMMAND_MAP.home` | 内部命令 `viewHome` 打开编辑器标签页 | 删除该命令，`home` 直接映射 VS Code 自动生成的 `watch-stock.view.focus`；菜单文案仍为「查看股票」 |
| 9 | 老板键 | 隐藏时 dispose 面板 | 改为 `setContext("watch-stock.show", false)` 隐藏视图 tab，不关面板（见 2.1）；菜单说明「隐藏状态栏并关闭股票面板」改为「隐藏状态栏与股票面板」；一键隐藏状态下主菜单不显示「查看股票」（视图不存在，聚焦会失败） |
| 10 | `commands.ts` 刷新触发 | 写配置本身会触发 `onDidChangeConfiguration → refresh()`，命令里又显式 `refresh()` 一次：添加股票 2 次请求，移除股票（`saveStocks` + `saveAlarms` + 显式调用）最多 3 次；闹钟触发时 `checkAlarms` 在刷新中写配置，又引发一次额外刷新 | 见下方说明 |

#10 刷新入口收敛方案：

- **单一入口 + 防抖**：`onDidChangeConfiguration` 作为配置类操作的唯一刷新触发点，加约 200ms 防抖，一次操作连续写多个配置只刷新一次；删除 add / remove / clear / sort 命令里的显式 `refresh()`。
- **闹钟配置不触发刷新**：只有 `priceAlarms` 变化时不刷新——闹钟增删不影响状态栏与视图显示，下一个 5 秒周期自然会检查；这样也消除了 `checkAlarms` 刷新中写配置引起的连锁刷新。实现上按"影响显示的配置键"列表逐个 `e.affectsConfiguration()` 判断（VS Code 事件不提供变更键列表）。
- **手动刷新保持直接调用**：「刷新行情数据」命令仍 `await refreshData()`，保证刷新完成后再提示。
- 防抖定时器在停用时一并清理。

## 四、配置与兼容性

- **配置项**：不新增、不删除、不改名，现有用户设置全部继续生效。
- **`enableColorful`**：保留（默认关闭即黑白，已满足隐蔽；开启是用户主动选择）。作用对象从旧面板改为新视图，仅控制涨跌色（开启用终端 ANSI 红绿，关闭用编辑器前景色）。说明文字从含糊的「是否开启彩色视图」改为「查看股票面板中涨跌以红绿色显示（状态栏不受影响）」，README 配置表同步。
- 其余配置项的声明（`scope`、`pattern`、`enumDescriptions`、`order` 等）本版本不动。
- **行为变化**（写入 CHANGELOG）：
  - 「查看股票」从编辑器标签页改为底部面板 `WATCH-STOCK` 视图，可拖到侧边栏；旧的编辑器标签页模式移除，无开关。
  - 「A股全览」拆为「指数」「板块」两个 tab，默认打开「自选」。
  - 个股详情由独立 tab 改为行内展开，分时图与成交量缩小为迷你尺寸。
  - 视图可见时自动刷新，不再需要手动点刷新；修改配置后视图即时生效。
  - 添加/移除股票等操作不再重复请求行情。
- **引擎要求**：`WebviewView`、`viewsContainers.panel` 在 `vscode ^1.96.0` 下均可用，不需要提升 engines。

## 六、风险与待验证

1. **容器隐藏行为**：视图 `when` 为 false 时，面板 tab 应随之消失（VS Code 会隐藏无可见视图的容器），需 F5 确认；若不生效，退路是隐藏时向视图推送空白内容并停止推送，tab 保留但无行情。
2. **启动恢复**：关闭编辑器时停在 `WATCH-STOCK`，重启后是否会弹出行情，需 F5 验证 `when: "watch-stock.show"` 延迟出现的方案是否有效；退路见 2.1「启动恢复」。
3. **面板高度**：展开区（2 行指标 + 分时 + 成交量）约 130px，用户把面板拉得很矮时可能放不下——展开区设最小高度，面板内纵向滚动兜底。
